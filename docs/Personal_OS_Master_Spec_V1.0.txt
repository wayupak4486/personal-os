PERSONAL OS — MASTER SPEC V1.0
Date: 21 August 2026
Status: Planning Complete / Ready for Development

==================================================
1. PRODUCT VISION
==================================================

Personal OS is a personal web app for managing life in one system.

Core question:
“What is most important today, and where am I spending my time, energy, and resources?”

Core areas:
- Goals
- Tasks
- 80/20 prioritization
- Time tracking
- Workout
- Gaming
- Payments & bills
- Daily planning
- Daily review
- Free data analysis
- Future AI companion

The product must stay minimal and useful. It must not become an app with so many features that using the system becomes work itself.


==================================================
2. PRODUCT PHILOSOPHY
==================================================

2.1 80/20 First
Focus on the small number of activities that create the largest results.

2.2 Daily Use First
The app should be useful immediately when opened in the morning.

2.3 Minimal Complexity
Every feature must have a clear purpose.

2.4 Free First
V1 must work without paid AI APIs or token costs.

2.5 AI Later
AI is an optional future layer, not a dependency for V1.

2.6 Personal First, Multi-user Ready
V1 is primarily for one person, but data uses user_id so multi-user support can be added later.


==================================================

==================================================

Morning
  -> See Today

==================================================
8. 80/20 ANALYSIS
==================================================

80/20 is an analysis layer, not a separate table.

Use:
- Impact
- Priority
- Goal relevance
- Effort
- Urgency
- Completion
- Time spent

Purpose:
Identify high-impact tasks and help decide what should be done first.

The algorithm can change without changing the database.


==================================================
9. TIME TRACKING
==================================================

Use manual Start / Stop.

Flow:
Start -> Work -> Stop

Store:
- Task
- Start time
- End time
- Duration

Purpose:
Understand not only what was completed, but where time was actually spent.

==================================================
12. PAYMENTS & BILLS
==================================================

This is NOT a full accounting system.

Purpose:
Know what needs to be paid and its current status.

Support:
- Recurring payments
- Variable payments
- Unknown amount
- Unknown due date
- Reminders
- Paid
- Partial
- Overdue
- Outstanding balance
- Payment history

Important real-life case:
A rent/dorm payment may not have a known amount or due date yet.

Example:
Dorm rent
Old outstanding: 3,500 THB
Current amount: unknown
Due date: unknown

Later:
Current amount: 4,200 THB
Due date: 5 Sep
Total: 7,700 THB

The system must allow “unknown” instead of forcing fake values.

==================================================
20. SCOPE GATE
==================================================

Before adding a feature, ask:

1. Does it support the Core Loop?
2. Is it necessary for V1?
3. How much complexity does it add?

Decision:
High value + low complexity -> Consider V1
High value + high complexity -> Future
Low value + high complexity -> Reject

Important:

- No analytics table
- No 80/20 table
- No outstanding_balance column
- No AI memory table in V1
- No notifications table initially

Calculated values should be calculated rather than duplicated.

23. SECURITY
==================================================

Use Supabase Row Level Security (RLS).

All personal data must be isolated by user_id.

Rule:
auth.uid() must match the row owner.

V1 is single-user in practice, but architecture is multi-user ready.

==================================================

Personal OS must never become:

If it only makes the software look sophisticated:
